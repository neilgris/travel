# 人生足迹总览 · 年度报告 — 设计文档

> 状态快照。对应 [ROADMAP.md](../../ROADMAP.md) 第三版「统计与洞察」两项。
> 叙事排版与地图复用旅程故事页，见 [2026-07-14-trip-story-page-design.md](2026-07-14-trip-story-page-design.md)。

## 1. 目标

把已录入的多年旅程数据整理成**两个可以「看」的视角**：

- **人生足迹总览页**：一屏纵览全部旅程——累计数字、里程碑、逐年对比。
- **年度报告**：某一年的叙事式回顾，一节一屏往下滚，将来可整页静态导出。

两页共享一套聚合层，口径只定义一次。总览页负责「纵览一生」，年度报告负责「细看一年」，逐年对比图是两者之间的入口。

**边界**：不动数据模型（无新表、无迁移），纯读现有数据；不做静态导出（ROADMAP 独立一项），但年度报告排版按「将来能整页导出」设计——不依赖服务端交互，图表数据全部内联。

## 2. 与现状的关系

旅程列表页 [trips/list.html](../../app/templates/trips/list.html) 目前承担着跨旅程消费看板：历史总花费、旅程数+总里程、到访国家（带国旗）、到访城市+Top5、最贵/最便宜旅程卡、整体消费构成环图、各旅程花费对比图，由 `stats.trips_overview()` 支撑。

这与「人生足迹总览页」的清单大面积重叠。**决策：看板整体搬到总览页**，列表页回归纯列表（标题 + 创建按钮 + 旅程列表 + 无旅程时的空状态）。理由是避免两处维护同一份 KPI，且总览页成为唯一的「统计首页」。

真正新增的内容只有：在途天数、里程碑、逐年对比。

## 3. 口径

所有口径在 `services/lifetime.py` 的模块文档字符串里写明，实现只此一处。

| 口径 | 规则 |
|------|------|
| **年份归属** | 整趟按 `start_date` 的年份，**不按天拆分** |
| **在途天数** | `end_date - start_date + 1` 求和，重叠日期去重 |
| **新解锁国家** | 该国家首次到访旅程的 `start_date` 年份 |
| **国家计数** | `City.country` 字段值原样计数，同现有列表页 |
| **里程** | 复用 `distance.trip_distance_km`（Leg 端点大圆距离累加，缺坐标的段跳过） |
| **金额** | 复用 `stats.to_cny`，逐条四舍五入后累加 |

**年份归属的取舍**：库里仅 1 趟跨年旅程（`201612 - 台北`，2016-12-29 → 2017-01-02）。按开始日期整趟归属让「一趟旅程始终是一个整体」，年度报告的旅程数与总览页对得上；代价是 2017 年 1 月那 2 天记在 2016。按天拆分虽更精确，但一趟旅程会同时出现在两年的报告里，叙事别扭，为 1 趟旅程的 2 天不值得。详见 DECISIONS。

**在途天数去重**：当前数据无任何两趟旅程日期重叠，去重是防御性的，不影响现有数字。

## 5. 聚合层接口

### `lifetime_stats(trips)` → 总览页数据

**累计**：`grand_total` / `trip_count` / `city_count` / `country_count` / `countries` / `total_distance_km` / `days_on_road`。前五个透传 `trips_overview()`，后两个新算。

**里程碑**（每个为 dict，数据不足时为 `None`，模板跳过该卡）：

| 键 | 含义 | 可点击 |
|----|------|--------|
| `first_abroad` | 最早含非中国城市的旅程（现数据：2012-09-18 马来西亚🇲🇾） | → 旅程详情 |
| `farthest_trip` | `trip_distance_km` 最大的旅程 | → 旅程详情 |
| `longest_trip` | 在途天数最多的旅程 | → 旅程详情 |
| `most_visited_city` | 覆盖旅程数最多的城市（排除北京，同现有 Top5 口径），带首末次日期 | 否 |
| `farthest_city` | 距北京直线距离最大的城市 | 否 |

**逐年**：`by_year` = 每年一条 `{year, trip_count, total_cny, distance_km, days_on_road, new_countries}`，**空档年补零**（现数据 2020、2022 缺席，补零让趋势图显出停摆期，这本身是信息）。`busiest_year` 标出旅程数最多的年份，供图上高亮。

### `year_report(trips, year)` → 年度报告数据

按第 6 节的六节组织。其中：

- **同比**：`prev_total_cny` 取**最近一个有旅程的年份**的总额（空档年跳过——2020 无旅程时，2021 与 2019 比，模板会写明具体年份）；没有更早的年份则为 `None`，模板不显示对比。
- **年度之最**：从那年所有 Entry 里选最贵的吃饭 / 最贵的住宿 / 花费最高的一天 / 里程最长的旅程。某项无记录则为 `None`；四项全 `None` 时整节跳过。
- **地图数据**：那年每趟的 Leg 汇总成 `{route, cities}`。

## 6. 页面

### 总览页 `/insights/`

自上而下：

1. **KPI 行**（六个）：总花费 / 旅程数 / 在途天数 / 总里程 / 国家数（带国旗）/ 城市数。较现有列表页新增「在途天数」，并把里程从旅程数的小字里提成独立卡。
2. **里程碑行**：五张卡，每张 emoji + 标题 + 主数值 + 副信息。三张旅程卡可点进详情。
3. **逐年对比图**：Chart.js 柱状图，X 轴年份（含补零空档年），柱高为总花费，`busiest_year` 高亮描边。**点柱子进 `/insights/<year>`**。tooltip 带该年旅程数 / 公里数 / 在途天数。
4. **既有看板**：最贵/最便宜旅程卡、整体消费构成环图、各旅程花费对比图，从 `list.html` 原样搬来。

搬迁时保留 `list.html` 里那段 Chart.js 性能注释与 `animation: false`——tooltip 跟随动画在 3000+px 高的对比图上会让 hover 明显卡顿，这个坑不能丢。

### 年度报告 `/insights/<year>`

六节纵向滚动，复用 `story.css` 的叙事排版语汇（大标题 + 留白 + 渐入），与故事页同一观感：

| 节 | 内容 |
|----|------|
| 1. 年份封面 | 大字年份 + 一句话概括（N 趟旅程 · N 个国家 · ￥xx,xxx · N 天在途） |
| 2. 足迹地图 | 那年所有旅程路线叠在一张图上 |
| 3. 新解锁国家 | 那年首次到访的国家，国旗 + 城市名；无则跳过本节 |
| 4. 旅程清单 | 每趟一张卡片（标题/日期/城市/花费），点进**故事页**（非详情页，叙事链路一路到底） |
| 5. 花费构成 | 总额 + 分类环图 + 与上一年对比（涨/跌 %） |
| 6. 年度之最 | 最贵的一顿饭 / 最贵的一次住宿 / 花得最多的一天 / 走得最远的一趟 |

- 顶部年份切换器（← 2015 · **2016** · 2017 →），只在有数据的年份间跳，同故事页「上一个/下一个旅程」导航的交互。
- 无效年份（库里无该年旅程）返回 404。

### 地图复用

`story-map.js` 的 `window.STORY_MAP.render()` 已被放映壳 `story-present.js` 复用，接口为 `{route, cities}`，年度报告第三次复用，不新写地图。

**但不套用它的取景裁剪**：那套逻辑（甩开出发地与远程中转）是为单趟旅程调的，一年多趟跨洲时会框偏。年度报告传全部城市让它自适应缩放到全包——「那年你走遍了哪」正需要看到全貌。
